# Personal Data Core 導入計画

AEGIS はすでに「今どこにいて何をしているか」の**粗い推論**と、「AEGIS が何をしたか」の**システムログ**を持っている。欠けているのは、ユーザーの過去を **Event → State → Evidence → 原データ** まで辿れる個人データベースである。MemoryManager を拡張せず、独立した **Personal Data Core (PDC)** を新設する。

## 現状（調査結果）

既存レイヤは役割が違う。混ぜない。

- **MemoryManager** ([ai-server/src/aegis_ai/memory/memory_manager.py](ai-server/src/aegis_ai/memory/memory_manager.py)): LLM が使う意味記憶。JSONL（episodic/semantic/facts）。原データなし。
- **UserStateManager** ([ai-server/src/aegis_ai/user_state/manager.py](ai-server/src/aegis_ai/user_state/manager.py)): 5–10 秒粒度の活動ラベル。`FORBIDDEN_KEYS` で text / clipboard / ui_tree / キー入力を**意図的に削除**。タイトル・URL は HMAC。LLM コンテキスト用。
- **JournalStore** ([ai-server/src/aegis_ai/journal/journal_store.py](ai-server/src/aegis_ai/journal/journal_store.py)): AEGIS バスイベントの全文 JSONL。メディアなし。保持期限なし。
- **AuditLog**: SQLite `data/audit.db`。プロンプト・画像を truncate する**損失ログ**。
- **PC poller**: `UserActivitySnapshot` は window + キー/マウス**回数**のみ。文字・URL・クリック対象なし。`browser_url_hash` は常に空。
- **Android**: foreground app / 通知ハッシュ / 粗い GPS。タップ対象・入力文字なし。
- **browser-server**: AEGIS 私有 Playwright。ユーザーの Chrome ではない。
- **room-server**: 環境値はモック。カメラ未実装。マイクは RMS のみで PCM 破棄。
- **依存**: SQLite（stdlib）、Chroma、cryptography AES-GCM、OTel。**未導入**: DuckDB / LanceDB / Graphiti / ffmpeg / OpenCV / Opus。

「19:32 Chrome で AGORA を開く → 返信欄クリック → 入力 → 送信」は**現状では再構成できない**。復元できるのは「19:32 頃 Chrome が前面、ブラウジング相当の入力があった」まで。

```mermaid
    J[Journal AEGIS events]
    MM[MemoryManager summaries]

  PC --> US

  US --> MM
  J --> LogsUI[Dashboard Logs]
```

## 方針: 何を再利用し、何を新設するか

**再利用**
- Manager 配線パターン（`RepairManager` と同様に `AegisRuntime` の sibling）
- Event バスへの subscribe（既存 `pc.user_activity.snapshot` / `android.*` を PDC にも流す）
- AES-GCM（[user_state ArchiveManager](ai-server/src/aegis_ai/user_state/manager.py)）
- Chroma（ベクトル。LanceDB は multimodal が必要になってから）
- SQLite FTS5（全文。新エンジン不要）
- PC UIA（[pc-server/src/uia.rs](pc-server/src/uia.rs)）を連続イベント源に拡張
- Android Accessibility をタップ対象・画面遷移の源に拡張
- PrivacySettings を PDC 用に拡張（既存 `screenshot_retention_hours` 等は紙の設定で未執行）

**新設**
- `PersonalDataCore` Manager + `data/personal_data/`
- Event / Observation / State / Evidence / Entity / Relationship / Fact / Inference のスキーマ
- Evidence オブジェクトストア（暗号化 blob）
- デバイス側コレクタ（PC UIA ストリーム、Android 操作ストリーム、Room 映像/音声）
- Timeline 検索 API とダッシュボード（Logs / Memory とは別ページ）

**触らない**
- MemoryManager の JSONL バックエンド
- UserState の FORBIDDEN_KEYS（LLM に生入力を流さないため残す）
- Journal を PDC に置き換えない（AEGIS 運用ログと個人ライフログは別）

## 1. Architecture

新パッケージ: [ai-server/src/aegis_ai/personal_data/](ai-server/src/aegis_ai/personal_data/)

- `core.py` — `PersonalDataCore`（ingest / query / retention / export）
- `models.py` — Pydantic（Observed / Generated / Inferred を Literal で固定）
- `event_store.py` — SQLite
- `evidence_store.py` — content-addressed ファイル + AES-GCM
- `state_projector.py` — Event からその時点の User/Device/Room State
- `ingest.py` — デバイス正規化（source_device / sensor / provenance）
- `search.py` — temporal + FTS + vector の合成
- `policy.py` — 収集オンオフ・保持・第三者データ

配線: [_build_runtime](ai-server/src/aegis_ai/runtime.py) で `UserStateManager` の直後に構築し、`AegisRuntime.personal_data_core` に載せる。`journal_store` のように private 属性へ隠さない。

収集は **push（デバイス → AI Server）** を主、既存の 5 秒 poller はフォールバック。PDC が落ちてもデバイスはローカルリングバッファに保持（後で drain）。

## 2. Data Model

共通フィールド（全レコード必須）:

- `id`, `timestamp_ms`, `duration_ms`
- `source_device` (`pc` / `android` / `browser-aegis` / `room` / `aegis`)
- `source_sensor` (`uia` / `accessibility` / `camera` / `mic` / `os` / `capability` …)
- `location` (`country/building/floor/room/zone/position` + `confidence`)
- `confidence` (0–1)
- `event_type`
- `entity_ids[]`
- `provenance` (`collector`, `schema_version`, `code_version`)
- `evidence_ids[]`
- `epistemics`: `observed` | `generated` | `inferred`  **混在禁止。1 レコード 1 値。**

レイヤ:

1. **Observation** — センサー生値（UIA ノード、RMS、フレームハッシュ）。epistemics=`observed`
2. **Event** — 「何が起きたか」（window.focused, ui.invoked, app.foreground）。Observation から決定的に作るなら `observed`、ルール結合なら `generated`
3. **State** — その瞬間のスナップショット（foreground app、room zone、posture）。定期投影。`generated`
4. **Evidence** — blob 参照（sha256、codec、bytes、retention_class）
5. **Entity** — user / app / url / room / file / person / window
6. **Relationship** — `(user)-[used {t0,t1}]->(app)` 時間区間付き（Graphiti の temporal validity 思想のみ）
7. **Fact** — 高信頼の観測事実。必ず `source_event_ids` + `source_evidence_ids`
8. **Inference** — LLM/CV/VAD。必ず `based_on_fact_ids` / `based_on_event_ids`。Fact テーブルに入れない
9. **Memory** — MemoryManager が PDC から生成。PDC 側には `memory_derivation` 行（どの Fact からどの memory_id を作ったか）だけ持つ

キーボードは **OS キーロガーにしない**。UIA Value/Text パターンで「フォーカス中コントロールの確定テキスト差分」と「password フィールドは本文を捨て control_kind=password だけ残す」。これで「返信欄に入力した」は再構成でき、秘密は落とす。

## 3. Storage（新規 DB は当面追加しない）

調査の結論: 今の依存で足りる。DuckDB / LanceDB / Graphiti / Postgres は **容量またはクエリが SQLite を超えてから**。

- **Event / Observation / State / Entity / Rel / Fact / Inference**: SQLite `data/personal_data/core.db`（audit.db と同型。WAL）
- **Evidence**: `data/personal_data/evidence/YYYY/MM/DD/<sha256>.<ext>.aesgcm` + SQLite メタ
- **全文**: SQLite FTS5（transcript、window title、URL、UI name）
- **ベクトル**: 既存 Chroma に collection `personal_data`（テキスト派生のみ）。画像/音声 embedding が必要になったら LanceDB を再検討
- **分析**: 初期は SQLite インデックス。イベントが数千万行 or 分析 SQL が重い時点で DuckDB + Parquet エクスポート
- **グラフ**: SQLite `entity` / `relationship`（`valid_from` / `valid_to`）。Graphiti は導入しない（Zep 思想は AdvancedMemory に既にある）

Journal JSONL は PDC の Event Store にしない。AEGIS 行動は PDC に **dual-write**（`source_device=aegis`）。

## 4. Collection（段階）

目標粒度は「Chrome → AGORA → 返信欄クリック → 入力 → 送信」。browser-server では不可能。**ユーザーの Chrome は PC UIA** で取る。

**Phase A — 既存イベントを PDC に生で吸う（センサー追加なし）**
- 現行 snapshot / android events を redaction せず PDC Observation に書く
- UserState は今どおり redacted のまま LLM へ

**Phase B — PC 構造化ストリーム**（[pc-server](pc-server/)）
- Window create/destroy/focus/title/bounds
- フォアグラウンド app / PID
- UIA: focus 変更、Invoke（クリック相当）、Value 変更（入力）、選択
- Chrome/Edge: UIA から URL / タブ名（可能な範囲）
- 画面ハッシュ（perceptual / block hash）。変化時のみ screenshot Evidence
- クリップボードは設定ゲート（既存 `clipboard_capture_enabled`）
- ターミナル: フォーカスが console のときの Value 差分（全文キーログではない）

**Phase C — Android**
- Accessibility: window 遷移、clickable の click、text changed（password 除外）
- foreground/background、通知本文は設定で raw vs hash
- screenshot は画面ハッシュ変化時のみ

**Phase D — Room**
- カメラ 720p。Motion / Person / SceneChange でトリガ。無変化区間は **State だけ残し Video は残さない**（要求どおり「捨てた時間」も Event 化）
- Pre 10s / Post 30–60s リングバッファ
- マイク: VAD 後 Opus。無音は保存しない。speaker は Inference
- Location 階層: 初期は設定ファイルの room/zone。Position はカメラ人物検出が来てから

**AEGIS 自身**: ToolBroker / chat / autonomous の実行を PDC Event に `source_device=aegis` で書く。User と同一 Timeline。

## 5. Compression

- Video: 720p、H.265 優先（ffmpeg）。Orange Pi で HW が無ければ software x265/AV1 は後回し（CPU を殺す）
- Audio: Opus、VAD セグメントのみ
- Screenshot: 変化時 JPEG/WebP。画面録画は短期 Evidence（例 24–72h）
- UI tree: 差分 JSON（前回との patch）。フルツリーは N 分に 1 回
- SQLite: 日次 VACUUM 不要。古い Observation は Parquet 退避を Phase 後期

## 6–8. Indexing / Search / Provenance

検索合成（「昨日 19 時に PC で何を開いていた？」）:

1. Temporal: `timestamp_ms` 範囲 + `source_device`
2. Keyword: FTS5（title/url/transcript/ui name）
3. Semantic: Chroma（派生テキスト。Raw は埋めない）
4. Graph: entity 近傍（app=Chrome, site=AGORA）
5. Evidence: ヒット Event の `evidence_ids` から blob

回答パス: Query → Timeline slice → Events → State → Facts → Evidence。Inference は「AEGIS の判断」として別表示。

Provenance 必須例:

- Fact「20:30 に AEGIS を開発していた」
- `source_event_ids`: window.focus #123, uia.value #124
- `source_evidence_ids`: screenshot #456
- `epistemics=inferred` ならカメラ姿勢など別 Inference をリンクし、Fact と混ぜない

## 9–10. Security / Retention

既存ギャップ: JSONL/journal/memory は平文。RetentionManager は数えるだけで消さない。Forget は MemoryStore のみ。

PDC は最初から:

- Encryption at rest: Evidence 必須。SQLite は SQLCipher を**追加しない**（新依存）。代わりにディスク全体 or ファイル AES-GCM。core.db は OS 権限 + 将来 SQLCipher をオプション
- Access: 既存 passkey。PDC API は fresh passkey（設定変更級）
- Audit: PDC の読取/エクスポート/削除を既存 AuditLog に書く
- 分類: `public / personal / sensitive / third_party / secret`。secret は本文を持たず control 種別のみ
- Retention class: `ephemeral_screen` / `short_media` / `long_event` / `forever_metadata`（設定可能）
- Export / 完全削除 / Integrity（sha256 再計算）
- 第三者（通知の相手、画面に映った他人）: `third_party` フラグと一括削除

UserState と PDC の契約: **LLM には UserState の redacted 要約だけ**。PDC raw はダッシュボードとローカル検索と Memory 派生ジョブ（local LLM 優先）だけ。

## 11. API

`/api/personal-data/`（[manager_routes.py](ai-server/src/aegis_ai/web/manager_routes.py)）:

- `GET /timeline?from&to&device`
- `GET /events/:id`（Observation / Evidence リンク付き）
- `GET /search?q&from&to`
- `GET /evidence/:id`（復号ストリーム、fresh auth）
- `POST /policy` 収集対象・保持
- `POST /export` `POST /delete`

Capability は `ai-server.personal_data.search` 等。チャットが PDC を使うときは **要約を LLM に渡し、原テキスト/画像はデフォルトで渡さない**。

## 12. Dashboard

観測の Logs（Journal）とは別。個人ドメインに **Timeline** ページを追加（[web-ui/src/navigation.ts](web-ui/src/navigation.ts) の `personal`）。

- 時間軸 + デバイスレーン（PC / Android / Room / AEGIS）
- Event クリックで State / Evidence / Provenance
- Observed と Inferred を色分け
- 既存 `user-state` ページは「AEGIS が見ている要約」として残す

## 13. Migration

- 既存 `data/user_state/timeline/*.jsonl` を Observation として import（redacted のまま。復元不能なハッシュは `observed` だが情報量低いと注記）
- Journal の `pc.user_activity.snapshot` / `android.*` をバックフィル可能
- Memory JSONL は移さない。以降 Sleep/派生が PDC Fact を参照するリンクを足す
- 設定: `PrivacySettings` に PDC 収集フラグ。デフォルトは Phase A のみ ON、キー入力・カメラ・マイクは OFF

## 容量見積（仮定: 在宅 PC 8h、スマホ 4h 操作、部屋カメラ常時だが録画は動きのみ）

保守的な「詳細記録・映像は間引き」ケース:

- メタデータ Event/State: 50–150 MB/日
- Screenshot 変化時: 20–80 MB/日
- 画面録画短期（当日のみ、計算から長期合計は除外）
- Room 動画（動き 30–60 分/日 720p H.265）: 200–500 MB/日
- 音声 Opus（発話 1–2h）: 10–30 MB/日

合計おおよそ **0.3–0.8 GB/日 → 10–25 GB/月 → 120–300 GB/年 → 1–3 TB/10年**（映像保持を「重要シーンのみ」に落とすと年 40–80 GB も可能）。

常時 720p 無間引きは年数 TB になり、要求仕様（無変化は捨てる）と矛盾するので採用しない。

## 実装フェーズ（コードを壊さない順）

1. **スキーマ + PersonalDataCore + SQLite + Evidence FS + API 骨格**。既存コレクタ dual-write。テストは append/query/provenance。
2. **ダッシュボード Timeline**（既存イベントだけでも「いつ・どのアプリ」は見える）。
3. **PC UIA ストリーム**（window/focus/invoke/value/url）。ここが「AGORA 返信」再構成の本丸。
4. **Android a11y ストリーム**。
5. **検索**（FTS + 時間 + 既存 Chroma）。
6. **Room カメラ/マイク**（ハードウェアと ffmpeg が揃ってから。新依存はこの段階で明示）。
7. **Memory 派生 + Sleep が PDC を読む**。Retention ワーカーを実際に削除する。
8. 必要になってから DuckDB / LanceDB / 人物検出を個別提案（Technology Decision Gate）。

## 最初の実装でやらないこと

- Graphiti / LanceDB / DuckDB / Postgres の導入
- OS キーロガー
- browser-server をユーザー Chrome の監視に転用
- MemoryManager 内部への生データ混入
- カメラ常時フル録画
